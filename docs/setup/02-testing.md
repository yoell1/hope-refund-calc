# 02. Testing 세팅 (pytest)

> 이 문서는 **AI 코딩 에이전트가 읽고 그대로 실행**하기 위한 작업 지시서다.
> 사용자는 개발 입문자다. 각 단계에서 무엇을 했는지 쉬운 말로 짧게 설명해 준다.
> 선행 조건: `01-linter.md` 완료 (`ruff check .` 통과 상태)

## 목표

`pytest` 한 줄로 테스트를 실행할 수 있고, **예시 테스트 3개 이상이 통과**하는 상태를 만든다.

## 배경 (사용자 설명용)

- 테스트는 "내가 만든 함수가 **의도대로 동작하는지** 자동으로 검산"하는 코드다.
- 세액 계산은 숫자 하나만 틀려도 결과가 다 틀리기 때문에, 정답을 아는 예시로 계속 확인하는 게 중요하다.

## 작업 순서

1. **설치 확인** — `pytest`가 `requirements-dev.txt`에 있는지 확인한다 (01에서 설치함).

2. **설정** — `pyproject.toml`에 추가한다.

   ```toml
   [tool.pytest.ini_options]
   testpaths = ["tests"]
   pythonpath = ["."]
   ```

3. **예시 코드 + 테스트 작성** — 우리 서비스의 구간 계산 함수로 만든다.
   - `app/services/bracket.py`에 `calc_bracket(amount, brackets)` 함수를 만든다.
     - `brackets`는 구간 목록(시작 `lower` · 끝 `upper`(없으면 None) · 비율 `rate` · 기본 금액 `base`)이다.
     - 금액이 들어가는 구간(시작 초과 · 끝 이하)을 찾아 `base + (amount - lower) * rate / 100`을 원 단위 정수로 돌려준다.
     - 금액이 0 이하이면 0을 돌려준다. (첫 구간 시작이 0이라 「시작 초과」 조건에 안 걸리기 때문)
   - `tests/test_bracket.py`에 테스트를 만든다. **DB 없이** 아래 구간 값을 테스트 안에 직접 넣는다. (2026 귀속 기본세율 앞 3구간 · 02_기준데이터.sql과 같은 값)

     | lower | upper | rate | base |
     | --- | --- | --- | --- |
     | 0 | 14,000,000 | 6 | 0 |
     | 14,000,000 | 50,000,000 | 15 | 840,000 |
     | 50,000,000 | 88,000,000 | 24 | 6,240,000 |

   - 위 표는 테스트 파일 맨 위에 `TAX_RATE_2026` 목록으로 직접 적어 둔다.
   - 테스트 작성 규칙:
     - **테스트 하나 = 확인 하나** (`def test_...` 하나에 `assert` 하나)
     - 본문은 `# Given` `# When` `# Then` 주석으로 3단 구분
     - 최소 케이스: `15,375,000 → 1,046,250`(노션 「연말정산 한 장 요약」 예시) · `14,000,000 → 840,000`(구간 끝) · `0 → 0`

   ```python
   def test_과세표준_15375000은_산출세액_1046250():
       # Given
       amount = 15_375_000
       # When
       result = calc_bracket(amount, TAX_RATE_2026)
       # Then
       assert result == 1_046_250
   ```

4. **실패하는 걸 한 번 보여주기** — `calc_bracket`에서 `- lower`를 잠깐 지워 `pytest`가 **실패**하는 것을 사용자에게 보여준 뒤, 원래대로 되돌려 다시 통과시킨다.

## 완료 기준 (모두 확인 후 결과를 보여줄 것)

- [ ] `pytest` → 모든 테스트 통과 (최소 3개)
- [ ] `ruff check .` → 여전히 에러 0개 (테스트 파일 포함)
- [ ] 일부러 깨뜨렸을 때 실패하는 것을 확인하고 원상 복구함
